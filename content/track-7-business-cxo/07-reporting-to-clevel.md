## 개념 설명

### 경영진 보고의 원칙 5가지

| 원칙 | 나쁜 예 | 좋은 예 |
|---|---|---|
| **1. 결론 먼저** (BLUF, Bottom Line Up Front) | 테스트 경과부터 시간순 설명 | "편의점 결제를 빼고 예정대로 출시할 것을 권고합니다" |
| **2. 결정 요청을 명시** | "참고 부탁드립니다" | "오늘 18시까지 옵션 1~3 중 선택이 필요합니다" |
| **3. 사실·추정·의견 구분** | "매출이 크게 줄 겁니다" | "재현 100%(사실), 영향 주문 비율 5~12%(추정, 근거: 사전 조사)" |
| **4. 숫자는 범위와 근거로** | "수천만 원 손실" | "일 2,100만~4,200만원 (이탈 40~80% 가정)" |
| **5. 나쁜 소식은 빨리, 대안과 함께** | 해결책을 찾을 때까지 보고 보류 | 발견 1시간 안에 1차 보고 + "대안 검토 중, 16시 업데이트" |

### 사례 — 일본 출시 D-2

```text
상황: 일본 신규 출시 D-2 오후, 최종 회귀 테스트 중 결함 3건 발견

결함 A  편의점 결제(コンビニ決済) 선택 → 결제번호 발급까지는 정상
        → 입금 완료 후에도 주문 상태가 '입금 대기'에서 바뀌지 않음 (재현 100%)
        신용카드 결제는 정상

결함 B  회원가입에서 전화번호를 전각 숫자로 입력하면 서버 500 오류
        + 오류 로그에 입력한 전화번호가 평문으로 기록됨 (스테이징에서 확인)

결함 C  가입 완료 이벤트가 분석 도구에 두 번 기록됨
        (사용자 화면 영향 없음, 가입 전환율이 실제의 약 2배로 집계)
```

### 같은 사건, 역할별 번역

**모두에게 같은 보고서를 보내지 않는다.** 역할마다 첫 문장이 달라야 한다.

| 대상 | 그 사람의 질문 | 핵심 결함 | 첫 문장 |
|---|---|---|---|
| **CEO** | 출시하나, 미루나? 선택지는? | A·B·C 종합 | "옵션 2(편의점 결제 제외 출시 + B 핫픽스)를 권고하며, 오늘 18시까지 결정이 필요합니다." |
| **CEO Japan** | 현지 고객·파트너 약속을 지킬 수 있나? | A | "편의점 결제를 출시 첫 주 제외하면 일정은 지킬 수 있습니다. 현지 공지 문구 승인이 필요합니다." |
| **CISO / 개인정보 보호책임자** | 개인정보가 노출되는가? | **B** | "전각 전화번호 입력 시 전화번호가 오류 로그에 평문 기록됩니다. 운영 반영 전이며, 로그 접근 범위 확인을 요청드립니다." |
| **CFO** | 돈이 어디서 새나? | A | "편의점 결제 입금이 주문으로 연결되지 않아 수동 대사·환불 비용이 발생할 수 있습니다." |
| **CRO** | 매출에 얼마나? | A | "편의점 결제를 빼면 해당 결제수단 선호 고객의 일부 전환 손실이 예상됩니다(범위 첨부)." |
| **CCO** | 고객 경험은? 지표는 믿을 만한가? | A, **C** | "입금했는데 주문이 안 되는 경험은 막아야 합니다. 또한 출시 첫 주 가입 전환율 지표가 2배로 부풀려져 있어 수정 전까지 판단에 쓰면 안 됩니다." |
| **CMO** | 출시 캠페인은 그대로 가나? | A, C | "캠페인 메시지에 편의점 결제가 있다면 수정이 필요하고, 캠페인 성과 지표는 C 수정 전까지 과대 집계됩니다." |
| **COO** | 운영으로 버틸 수 있나? | A | "옵션 1 선택 시 편의점 결제 주문을 CS가 수동 확정해야 하며, 일 처리량 추정치를 첨부합니다." |
| **CTO** | 원인과 수정 규모는? | A, B | "B는 입력 정규화 누락 + 로그 마스킹 누락으로, 수정 4시간·재검증 3시간 추정입니다." |
| CHRO | — | — | **보고하지 않는다.** 대상을 고르는 것도 판단이다 |

**B는 일정과 무관하게 즉시 CISO·개인정보 보호책임자에게 간다.** 보안·개인정보 이슈는 출시 판단 회의를 기다리지 않는다.

### 1장 보고서 — CEO에게 가는 최종본

```text
[결정 요청]  일본 출시(D-2) 진행 방식 — 오늘 18:00까지
[권고]      옵션 2: 편의점 결제 제외 출시 + 결함 B 핫픽스 후 출시

[사실]
 A. 편의점 결제 입금 후 주문 미확정 (재현 100%, 신용카드 정상)
 B. 전각 전화번호 입력 시 500 오류 + 전화번호 평문 로그 (스테이징 확인, 운영 미반영)
 C. 가입 완료 이벤트 중복 기록 (사용자 영향 없음, 분석 지표만 영향)

[영향 — 추정]
 A. 편의점 결제 주문 전량 수동 확정 필요. 결제수단 비중은 사전 조사 기준 범위로 첨부
 B. 수정 없이 출시하면 운영 로그에 개인정보 적재 → CISO·개인정보 보호책임자 확인 요청 완료
 C. 첫 주 가입 전환율이 실제의 약 2배로 보임 → 캠페인 판단 왜곡

[옵션]
 1. 예정대로 전체 출시     A는 CS 수동 처리, B 위험 그대로           → 비권고
 2. 편의점 결제 제외 출시  B 핫픽스 필수(수정 4h + 재검증 3h),       → 권고
                          A는 다음 주 배포, C는 출시 후 3일 내 수정
 3. 1주 연기              전 결함 수정 후 출시, 캠페인·파트너 일정 영향 → CEO Japan 확인 필요

[필요한 결정]  옵션 선택 / 편의점 결제 미지원 공지 문구 승인 (CEO Japan·CCO)
[다음 업데이트] B 핫픽스 검증 결과 — 내일 12:00
```

이 보고서에 **없는 것**도 보라.

- 스택 트레이스, API 이름, 테스트 케이스 번호 → **CTO용 첨부**로 뺀다
- "QA는 출시에 반대합니다" → QA는 옵션과 리스크를 제시한다 (트랙 1-07)
- 결함 전체 목록 → 결정에 영향 주는 3건만

### 역할별로 받게 될 질문 — 미리 답을 준비한다

| 질문자 | 예상 질문 | 준비할 답 |
|---|---|---|
| CEO | "옵션 2로 가면 다음 주엔 확실히 되나?" | A 수정 추정 공수, 재검증 계획, 불확실성 |
| CFO | "수동 처리하면 하루 인건비가 얼마나 드나?" | 건당 처리 시간 × 예상 건수 × 인건비 |
| CISO | "운영 로그에 이미 들어간 데이터는 없나?" | 운영 반영 여부 확인 근거, 스테이징 로그 삭제 조치 |
| CEO Japan | "경쟁사도 편의점 결제를 지원하나?" | 모르면 **"확인해서 16시에 답드리겠습니다"** |
| CCO | "C 때문에 지금까지 본 지표 중 틀린 게 있나?" | 이벤트 중복 시작 시점, 영향받은 대시보드 |

**모르는 질문에는 추정으로 답하지 않는다.** 경영진 앞에서 틀린 숫자 하나가 보고서 전체의 신뢰를 무너뜨린다.

### 에스컬레이션 경로 정하기

| 이슈 유형 | 누구에게 | 언제 |
|---|---|---|
| 보안·개인정보 | CISO, 개인정보 보호책임자 | **즉시**, 일정 무관 |
| 법·규제 표기 | CLO/법무, (해외면) 현지 법인장 | 출시 판단 전 |
| 매출·결제 | CRO, CFO | 출시 판단 회의 |
| 고객 경험·지표 | CCO, CMO | 출시 판단 회의 |
| 출시 여부 | CEO (또는 위임받은 사람) | 옵션 정리 후 |

**이 표를 출시 전에 팀과 합의해 두는 것**이 가장 좋은 에스컬레이션이다.

### AI로 역할별 초안 만들기 — 그리고 검증하기

역할별 번역은 AI가 잘하는 일이다. 하지만 **보고서의 신뢰는 QA가 진다.** 트랙 6-08의 검증 관점을 그대로 적용한다.

| AI 초안에서 자주 생기는 문제 | 확인 방법 |
|---|---|
| 입력에 없는 숫자를 만들어낸다 ("매출 약 3억원 손실") | 모든 숫자의 출처를 표시해 본다 |
| 심각도를 완화하거나 과장한다 | 원래 결함 기술과 문장을 대조한다 |
| 추정을 사실처럼 쓴다 | "사실/추정" 라벨을 직접 붙인다 |
| 보안 이슈를 일반 결함과 같은 줄에 둔다 | 보안·개인정보가 별도·즉시 경로인지 확인 |
| 모든 임원에게 같은 내용을 복붙한다 | 첫 문장이 역할마다 다른지 확인 |

## 왜 채용시장이 요구하는가

- 면접 질문: **"경영진에게 품질 이슈를 설명하고 결정을 이끌어낸 경험이 있나요?"** — 시니어·리드 면접의 단골이다.
- 공고의 **"커뮤니케이션 능력"** 은 결국 이 번역 능력이다. 결함을 찾는 능력과 **결정으로 연결하는 능력**은 다르게 평가된다.
- AI가 테스트와 리포트 초안을 만들수록, **무엇을 누구에게 어떤 순서로 말할지 판단**하는 사람의 가치가 커진다.
- 출시 D-2 같은 압박 상황에서 **옵션을 설계해 본 경험**은 강한 이력이다.

## 실습 과제

### 과제 1 — 역할별 한 줄 번역 (15분)

위 사례를 가리고, 아래 결함으로 **직접** 표를 채운다.

```text
결함: 연간 구독 자동 갱신일에 카드 결제가 실패한 사용자가
      '구독 해지' 상태로 바뀌지 않고 7일간 유료 기능을 계속 사용한다.
      동시에 실패 안내 메일이 발송되지 않는다.
```

| 대상 | 그 사람의 질문 | 첫 문장 |
|---|---|---|
| CEO | | |
| CFO | | |
| CRO | | |
| CCO | | |
| COO | | |
| 보고하지 않을 대상과 이유 | | |

### 과제 2 — 1장 보고서 (20분)

본인이 실제로 겪었거나 가상으로 만든 출시 직전 이슈로, 위 템플릿을 채운다.

- [결정 요청]과 [권고]가 맨 위에 있는가
- 사실과 추정이 분리됐는가
- 옵션이 2개 이상이고 각각 리스크가 있는가
- 기술 상세는 첨부로 뺐는가

### 과제 3 — 30초 구두 보고 (5분)

엘리베이터에서 CEO를 만났다고 가정한다. 과제 2의 내용을 **30초 안에** 소리 내어 말하고 녹음한다.

```text
[결론 1문장] → [이유 1문장] → [필요한 결정 1문장]
```

다시 들으며 **기술 용어가 몇 개 나왔는지** 센다.

### 과제 4 — 예상 질문 방어 (10분)

과제 2의 보고서에 대해 CEO·CFO·CISO가 할 질문을 각 2개씩 쓰고 답을 준비한다.
**답할 수 없는 질문**에는 "언제까지 확인하겠다" 는 답을 쓴다.

### 과제 5 — AI 초안 검증 (15분)

AI 실습 도우미에 위 **일본 출시 D-2 사례**를 그대로 붙여넣고 요청한다.

> 이 상황을 CEO, CISO, CCO에게 각각 보낼 보고 초안을 작성하라.

| 확인 항목 | CEO | CISO | CCO |
|---|---|---|---|
| 입력에 없는 숫자를 만들지 않았는가 | | | |
| 첫 문장이 역할별로 다른가 | | | |
| 결정 요청과 기한이 있는가 | | | |
| 사실/추정이 구분됐는가 | | | |
| CISO 보고가 "즉시·일정 무관" 으로 분리됐는가 | | | |

### 과제 6 — 면접 답변 만들기 (10분)

과제 2를 **STAR**(상황·과제·행동·결과) 형식으로 2분 답변으로 만든다.
**결과(Result)** 에는 가능한 한 숫자(지연 일수, 막은 손실, 줄어든 문의)를 넣는다.

## 자가 체크리스트

- [ ] 경영진 보고 원칙 5가지(결론 먼저, 결정 요청, 사실/추정 구분, 범위 숫자, 빠른 보고)를 안다
- [ ] 같은 결함 묶음을 역할별로 다른 첫 문장으로 번역할 수 있다
- [ ] 보고하지 않을 대상을 고르는 것도 판단임을 안다
- [ ] 보안·개인정보 이슈는 출시 일정과 무관하게 즉시 보고함을 안다
- [ ] 1장 보고서에 결정 요청·권고·사실·추정·옵션·다음 업데이트를 넣을 수 있다
- [ ] 기술 상세를 본문이 아닌 첨부로 분리할 수 있다
- [ ] "QA는 반대합니다" 대신 옵션과 리스크로 말할 수 있다
- [ ] 역할별 예상 질문을 미리 준비할 수 있다
- [ ] 모르는 질문에 추정 대신 확인 시점으로 답할 수 있다
- [ ] 이슈 유형별 에스컬레이션 경로를 표로 만들 수 있다
- [ ] AI가 만든 보고 초안에서 만들어진 숫자·심각도 왜곡을 걸러낼 수 있다
- [ ] 보고 경험을 STAR 형식 면접 답변으로 만들 수 있다
