## 개념 설명

### CSO — 회사의 미래 성장 방향과 신사업 전략

CEO가 전략을 **세우고, 전달하고, 실행되게 하고, 유지하는 일**을 전담시키려고 두는 자리다.
HBR의 CSO 연구(2007)에 따르면 CSO는 순수한 기획가라기보다 **실행을 챙기는 사람**에 가깝고, 운영 경험이 많은 임원이 맡는 경우가 많다.

| 하는 일 | 예 |
|---|---|
| 중장기 전략 수립 | 3~5년 성장 방향, 집중할 시장 |
| 신사업 발굴·검토 | 새 국가 진출, 새 상품군, 새 수익모델 |
| M&A·제휴 | 인수 대상 검토, 파트너십 |
| 시장·경쟁 분석 | 시장 규모, 경쟁사 움직임 |
| 전략 과제 실행 관리 | OKR, 분기 로드맵 점검 |

> **약어 주의** — CSO는 Chief **Sales** Officer(영업), Chief **Security** Officer(보안)일 수도 있다. (7-01)

### CSO의 언어와 QA의 연결

CSO가 쓰는 말은 **시장, 기회, 로드맵, 우선순위**다. QA와 연결되는 지점은 **"새로움"** 이다.

| 전략 결정 | QA가 가져가야 할 리스크 |
|---|---|
| 새 국가 진출 (예: 일본) | 현지화, 현지 결제, 현지 법규 (7-02) |
| 새 결제·수익모델 (구독, 후불) | 상태전이, 정산 데이터 정합성 (트랙 1-03, 2-05) |
| 인수한 서비스 통합 | 계정 통합, 데이터 이관, 중복 회원 |
| AI 기능 도입 | 환각·편향 검증, 규제 대응 (트랙 4, 7-06) |
| 새 플랫폼 (웹 → 앱) | 디바이스 매트릭스, 모바일 자동화 (트랙 3-06) |

**전략 발표 자료를 QA가 읽어야 하는 이유**가 여기 있다. 6개월 뒤 테스트해야 할 것이 지금 발표된다.

```text
전략 로드맵: "내년 2분기 일본 출시, 3분기 후불결제 도입"
QA 준비:     1분기 — 일본어 테스트 환경·디바이스, 현지화 TC 설계
             2분기 — 현지 결제 대행사 샌드박스 연동 테스트
             3분기 — 후불결제 상태전이·정산 대사 자동화
```

전략 과제의 **"완료" 정의에 품질 기준을 넣자고 제안**하는 것도 QA의 일이다. "출시" 가 아니라 "출시 + 결제 성공률 99% 이상 유지" 처럼.

### CFO — 돈과 관련된 모든 것

| 하는 일 | 설명 |
|---|---|
| 재무 계획·예산 | 연간 예산 편성, 부서별 배분 |
| 회계·결산 | 장부, 재무제표, 감사 대응 |
| 자금 관리 | 현금흐름, 운영 자금 |
| 투자·IR | 투자 유치, 주주·투자자 커뮤니케이션 |
| 재무 리스크·내부통제 | 정산 오류, 부정 방지 |

### CFO의 언어 — QA 예시로 익히기

| 용어 | 뜻 | QA 예시 |
|---|---|---|
| 예산 (Budget) | 연간 계획된 지출 | 테스트 도구 라이선스, 디바이스 팜 |
| CAPEX / OPEX | 자본적 지출(자산 구입) / 운영 비용 | 테스트 단말 구매 vs 클라우드 디바이스 팜 구독 |
| ROI | (얻은 가치 − 비용) ÷ 비용 | 자동화 투자 수익 |
| 회수 기간 (Payback) | 투자금을 되찾는 데 걸리는 기간 | 자동화 구축비를 몇 개월 만에 회수하나 |
| TCO | 총소유비용 | **오픈소스도 유지보수 인건비가 든다** |
| 기회비용 | 다른 곳에 썼다면 얻었을 가치 | 수동 회귀에 쓴 시간 = 못 한 탐색 테스트 |

회계 처리(비용인지 자산인지)는 회사 기준을 따르므로 **CFO 조직에 확인**한다. QA가 정할 일은 아니다.

### 품질 비용(COQ) — 품질을 돈으로 보는 프레임

품질경영에서 오래 쓰인 **PAF 모델**이다. 품질에 드는 비용을 네 칸으로 나눈다.

| 구분 | 뜻 | 소프트웨어 예 |
|---|---|---|
| **예방 비용** (Prevention) | 결함이 생기지 않게 | 요구사항 리뷰, 테스트 설계 교육, 정적 분석 도입 |
| **평가 비용** (Appraisal) | 결함을 찾기 위해 | 테스트 수행, 자동화 유지, 테스트 환경 |
| **내부 실패 비용** (Internal failure) | 출시 전에 찾은 결함 처리 | 수정·재테스트, 릴리즈 지연 |
| **외부 실패 비용** (External failure) | 고객이 찾은 결함 처리 | 핫픽스, CS 문의, 환불·보상, 이탈, 평판 |

**CFO에게 보이는 것은 앞의 두 칸(QA 인건비, 도구비)뿐인 경우가 많다.** 외부 실패 비용은 CS·환불·이탈로 흩어져 있어 "품질 비용" 으로 집계되지 않는다.
QA가 할 일은 **숨은 네 번째 칸을 보이게 만드는 것**이다.

```text
지난 분기 결제 장애 1건의 외부 실패 비용 (예시)
  CS 문의 처리        1,200건 × 건당 처리비 3,000원    = 360만원
  보상 쿠폰           실제 사용액                     = 900만원
  긴급 핫픽스         개발 3명 × 12시간 × 시간당 6만원  = 216만원
  ─────────────────────────────────────────────────────
  합계                                                ≈ 1,476만원  (+ 이탈 고객은 별도 추정)
```

> **"결함은 늦게 발견될수록 10배, 100배 비싸다"** 는 수치는 널리 인용되지만, 근거 데이터가 오래됐고 일반화가 논쟁적이다.
> CFO 앞에서는 **남의 배수 대신 우리 회사 데이터**를 쓴다. 되물으면 답할 수 있어야 하기 때문이다.

### 자동화 ROI — CFO에게 가져갈 수 있는 형태

```text
[가정 — 반드시 우리 팀 실측값으로 바꾼다]
수동 회귀 1회          40시간 (QA 2명 × 20시간)
릴리즈 빈도            월 2회 → 연 24회
시간당 인건비          5만원 (회사 부담분 포함, 예시)
자동화 구축            400시간 (1회성)
자동화 유지보수        월 20시간
자동화 후 남는 수동    1회 8시간

[연간 비용]
수동 유지       40h × 24회 × 5만원                  = 4,800만원
자동화 1년차    구축 400h × 5만원                   = 2,000만원
              + 유지 20h × 12개월 × 5만원           = 1,200만원
              + 잔여 수동 8h × 24회 × 5만원          =   960만원
              = 4,160만원    → 1년차 절감   640만원
자동화 2년차~   1,200만원 + 960만원                 = 2,160만원    → 연 2,640만원 절감

[회수 기간]
월 절감 = (4,800 − 2,160) ÷ 12 = 220만원
구축비 2,000만원 ÷ 220만원 ≈ 9.1개월
```

**CFO는 반드시 가정을 흔든다.** 민감도를 미리 계산해 간다.

| 시나리오 | 유지보수 (월) | 월 절감 | 회수 기간 |
|---|---|---|---|
| 기본 | 20시간 | 220만원 | 약 9.1개월 |
| 유지보수 2배 | 40시간 | 120만원 | 약 16.7개월 |
| 릴리즈 월 4회로 증가 | 20시간 | 540만원 | 약 3.7개월 |

(릴리즈 월 4회: 수동 40h×4×5만원 = 800만원/월, 자동화 100만원 + 8h×4×5만원 = 260만원/월 → 절감 540만원)

돈 외의 효과(릴리즈 리드타임 단축, 야간 배포 부담 감소)는 **보조 근거**로 붙인다.
그리고 **"인력 감축"** 이 아니라 **"같은 인력으로 더 넓은 범위를 검증"** 으로 제안한다. 숫자는 같아도 조직이 받아들이는 방식이 다르다.

### CSO와 CFO가 함께 던지는 질문

> "이 신사업에 품질 투자를 얼마나 해야 하는가?"

답의 틀은 트랙 1-01의 **리스크 기반 테스트**와 같다.

```text
품질 투자의 상한 ≈ (실패 시 예상 손실) × (발생 가능성)
```

정밀한 계산보다 **"이 기능이 실패하면 얼마를 잃는가"** 를 CSO·CFO와 같은 표로 본다는 것이 중요하다.

## 왜 채용시장이 요구하는가

- 리드·매니저 공고에 **"테스트 도구 선정 및 도입"**, **"자동화 효과 측정"** 이 들어간다. 결국 예산 설득이다.
- 면접 질문: **"자동화 도입 효과를 어떻게 측정했나요?"** — 시간·금액·회수 기간으로 답하면 강하다.
- 도구 비교(트랙 3-07)를 **라이선스 가격이 아니라 TCO** 로 말할 수 있으면 시니어로 보인다.
- 전략 로드맵에서 **6개월 뒤 테스트 리스크를 미리 꺼내는 QA** 는 드물고, 그래서 눈에 띈다.

## 실습 과제

### 과제 1 — 우리 팀 품질 비용 4분류 (15분)

지난 한 달 팀 활동을 네 칸에 나눠 적는다. 시간이 대략이어도 된다.

| 구분 | 활동 | 추정 시간/비용 |
|---|---|---|
| 예방 | | |
| 평가 | | |
| 내부 실패 | | |
| 외부 실패 | | |

**외부 실패 칸에 무엇이 빠져 있는지** 확인한다. CS 부서·환불 데이터를 누가 가지고 있는가?

### 과제 2 — 자동화 ROI 계산 (20분)

위 템플릿의 가정을 **본인 팀 값**(또는 합리적인 가상값)으로 바꿔 계산한다.

1. 1년차·2년차 비용과 절감액
2. 회수 기간
3. 민감도 시나리오 2개 — 유지보수 증가, 릴리즈 빈도 변화
4. 가정마다 **근거**를 한 줄씩

### 과제 3 — CFO용 도구 도입 제안 1장 (15분)

유료 테스트 도구 하나(디바이스 팜, 테스트 관리 도구 등)를 도입한다고 가정한다.

```text
[요청]      무엇을, 얼마에, 언제부터
[비용]      연간 비용 (라이선스 + 도입 인건비 + 유지)
[효과]      절감 시간 × 인건비, 줄어드는 실패 비용
[회수 기간]
[대안]      도입하지 않을 때 / 오픈소스로 할 때 (TCO)
[리스크]    효과가 안 나올 조건
```

### 과제 4 — 전략 발표문 → QA 리스크 (15분)

가상의 전략 발표를 읽는다.

> "내년 상반기에 일본 시장에 진출하고, 하반기에는 인수한 결제 스타트업의 후불결제를 우리 앱에 통합한다."

1. QA 리스크 5개를 뽑는다
2. 각 리스크를 **몇 분기 전에 준비해야 하는지** 적는다
3. 전략 과제의 완료 기준에 넣을 품질 지표 2개를 제안한다

### 과제 5 — AI 결과 검증 (10분)

AI 실습 도우미에 요청한다.

> 테스트 자동화 도입의 ROI를 계산하는 예시를 만들어라.

| 확인 항목 | 결과 |
|---|---|
| 가정을 명시했는가 | |
| **유지보수 비용**을 넣었는가 (가장 자주 빠진다) | |
| 1년차(구축 포함)와 이후를 구분했는가 | |
| **산수를 직접 다시 계산**했을 때 맞는가 | |
| 출처 없는 "100배" 같은 수치를 인용하지 않았는가 | |

## 자가 체크리스트

- [ ] CSO가 전략 수립뿐 아니라 실행을 챙기는 역할임을 안다
- [ ] CSO 약어가 Strategy·Sales·Security일 수 있음을 안다
- [ ] 전략 결정(새 국가, 새 결제, M&A, AI)을 QA 리스크로 번역할 수 있다
- [ ] 전략 로드맵을 보고 QA 준비 시점을 역산할 수 있다
- [ ] CFO가 하는 일 5가지를 말할 수 있다
- [ ] CAPEX/OPEX, ROI, 회수 기간, TCO, 기회비용을 QA 예로 설명할 수 있다
- [ ] 품질 비용 PAF 모델의 네 칸을 소프트웨어 예로 채울 수 있다
- [ ] 외부 실패 비용이 흩어져 있어 보이지 않는다는 점을 설명할 수 있다
- [ ] "100배" 같은 일반 수치 대신 자사 데이터를 써야 하는 이유를 안다
- [ ] 자동화 ROI를 1년차·이후로 나눠 계산하고 회수 기간을 구할 수 있다
- [ ] 민감도 분석으로 가정 변화에 대비할 수 있다
- [ ] 자동화를 "인력 감축" 이 아닌 "검증 범위 확대" 로 제안할 수 있다
