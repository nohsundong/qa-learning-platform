## 개념 설명

### 세 역할을 한 줄로

| | 책임 | 늘 던지는 질문 |
|---|---|---|
| **CISO** | 회사의 중요한 정보와 보안 시스템을 해킹·유출로부터 지킨다 | "이게 뚫리면 무엇이 새는가?" |
| **CIO** | 사내 IT 시스템을 관리한다 | "업무가 멈추지 않는가, 비용은 적정한가?" |
| **CDO** | 회사의 디지털 전환(DX)을 이끈다 | "디지털로 사업 방식을 어떻게 바꿀 수 있는가?" |

세 역할은 **작은 회사에서는 한 사람이 겸하고**, 큰 회사에서는 서로 견제하도록 **분리**하기도 한다.

### CISO — 정보보호최고책임자

2021년 개정된 정보통신망법은 CISO의 업무를 이렇게 정리한다.

| 업무 | QA와의 연결 |
|---|---|
| 정보보호 계획 수립·시행·개선 | 보안 테스트가 릴리즈 절차에 들어가 있는가 |
| 정보보호 실태의 정기 감사·개선 | 테스트 환경·데이터 접근 권한 점검 |
| 정보보호 위험 식별·평가·대책 | QA가 찾은 보안 결함이 위험 목록의 입력이 된다 |
| 정보보호 교육·모의훈련 | 피싱 훈련, 침해사고 대응 훈련 |

CISO가 보는 숫자: **취약점 조치 기간**, 보안 사고 건수, 모의훈련 결과, 인증(ISMS·ISMS-P) 유지 여부.

### 한국에서 CISO는 '선택'이 아니다

| 항목 | 내용 |
|---|---|
| 근거 | 정보통신망법 **제45조의3** |
| 의무 | 정보통신서비스 제공자는 CISO를 **지정하고 과학기술정보통신부장관에게 신고** |
| 신고 면제 | 일정 규모 미만 기업은 신고가 면제되고, 이 경우 **대표자를 CISO로 간주** |
| 중소기업 | 대표자 또는 부장급 직원도 CISO로 지정 가능 |
| **겸직 제한 대상** | 직전 사업연도 말 **자산총액 5조원 이상**, 또는 **ISMS 인증 의무대상자 중 자산총액 5천억원 이상** → 이사(집행임원 포함)급으로 지정하고 다른 업무 겸직 제한 |
| 위반 시 | 지정·신고 의무 위반은 **3천만원 이하 과태료** (제76조) |

세부 기준은 시행령 개정으로 바뀔 수 있다. **정확한 적용 여부는 원문과 법무 확인**이 원칙이다. QA가 외울 것은 숫자보다 **"CISO는 법이 요구하는 책임자이고, 보안 이슈의 공식 창구다"** 라는 사실이다.

### CISO와 개인정보 보호책임자(CPO)는 다르다

| | CISO | 개인정보 보호책임자 (CPO) |
|---|---|---|
| 근거 법 | 정보통신망법 | 개인정보 보호법 (제31조) |
| 범위 | 정보·시스템 전체의 보안 | 개인정보의 수집·이용·제공·파기 |
| QA가 묻는 것 | 취약점, 접근통제, 로그 | 수집 동의, 마스킹, 보관 기간, 파기 |

2024년 3월 15일 시행된 개인정보 보호법 시행령 개정으로, 일정 기준 이상 기업의 CPO에게는 **개인정보 보호 경력 2년 이상을 포함해 개인정보 보호·정보보호·정보기술 경력 합산 4년 이상**의 자격요건이 생겼다. 기존 지정자에 대한 유예기간은 **2026년 3월 14일**까지였다.

작은 회사는 CISO와 CPO를 **한 사람이 겸하는 경우가 많다.** 누가 맡고 있는지 이름을 알아두는 것이 QA의 첫 준비다.

### QA가 CISO와 만나는 세 지점

#### 1. 보안 결함 보고 — 일반 결함과 경로가 다르다

| 일반 결함 | 보안 결함 |
|---|---|
| 팀 전체가 보는 트래커에 공개 등록 | **접근이 제한된** 보안 티켓 또는 지정 채널 |
| 재현 절차를 자세히 | 재현 절차는 **제한된 곳에만**. 공개 채널에 공격 방법을 쓰지 않는다 |
| 우선순위 회의에서 결정 | **발견 즉시** 보고, 일정과 무관 |
| 운영에서 재현해도 됨 | **운영 환경에서 공격 재현 금지.** 테스트 환경에서만 |

QA가 실무에서 자주 찾는 보안 결함.

| 결함 | 어디서 배웠나 |
|---|---|
| URL의 ID만 바꾸면 남의 데이터가 보인다 (IDOR) | 트랙 6-01 |
| UI는 막혔는데 API로는 된다 | 트랙 2-02, 6-01 |
| 오류 응답에 스택 트레이스·쿼리가 노출 | 트랙 2-06 |
| **로그에 개인정보가 평문으로 남는다** | 7-07 사례 B |
| 세션 쿠키에 HttpOnly·Secure 플래그 없음 | 트랙 6-01 |

```text
[보안 결함 보고 — 제한 채널]
제목        회원가입 오류 시 전화번호가 애플리케이션 로그에 평문 기록
발견 환경   스테이징 (운영 반영 여부: 미반영 확인 / 확인 중)
영향 데이터 전화번호 (개인정보)
노출 범위   로그 조회 권한자 N명, 로그 보존 기간 30일
재현 조건   전각 숫자 전화번호 입력 → 500 오류 발생 시
임시 조치   스테이징 로그 해당 구간 삭제 요청
요청 사항   CISO·개인정보 보호책임자 영향 판단, 운영 로그 점검
```

#### 2. 테스트 데이터 — 가장 흔한 사고 경로

ISMS-P 인증기준에는 QA 업무와 직접 닿는 항목이 있다.

| 인증기준 | 요지 | QA 실무 |
|---|---|---|
| **2.8.3 시험과 운영 환경 분리** | 개발·시험 환경과 운영 환경을 분리하고, 운영 이관은 통제된 절차로 | 운영에서 직접 테스트하지 않는다, 배포 전 시험·인수 절차 기록 |
| **2.8.4 시험 데이터 보안** | 시험 과정에서 운영 데이터 유출 방지. 운영 데이터를 불가피하게 쓰면 **책임자 승인, 접근·유출 모니터링, 시험 후 삭제** | 합성 데이터·마스킹 우선, 운영 덤프 사용 시 승인과 삭제 기록 |

**실제로 가장 자주 새는 곳은 결함 리포트 첨부물이다.**

```text
□ 스크린샷에 실제 고객 이름·전화번호·주소가 보이는가
□ 첨부한 로그·HAR 파일에 토큰, 쿠키, 개인정보가 들어 있는가
□ 운영 DB 조회 결과를 이슈 트래커에 붙여넣었는가
□ 운영 데이터를 외부 AI 도구에 붙여넣었는가 (트랙 4)
□ 테스트용으로 받은 운영 덤프가 개인 PC에 남아 있는가
```

#### 3. 인증 심사 증적

ISMS·ISMS-P 인증을 받은 회사는 심사 때 **변경관리와 시험 수행 기록**을 보여줘야 한다. 인증기준 2.8.2(보안 요구사항 검토 및 시험)는 보안 요구사항이 실제로 반영됐는지 시험하라고 요구한다.

**QA의 테스트 계획·결과 기록이 곧 심사 증적**이 된다. 그래서 인증 기업에서는 "테스트는 했는데 기록이 없다" 가 결함만큼 문제가 된다.

### CIO — 사내 IT 시스템 관리

| 하는 일 | 예 |
|---|---|
| 업무 시스템 | ERP, 회계, 그룹웨어, HR 시스템 |
| 인프라·네트워크 | 사내망, 계정·권한, 기기 관리 |
| IT 예산·구매 | SaaS 도입 검토, 라이선스 |
| 업무 연속성 | 백업, 재해복구(DR) |

제품 기술을 맡는 **CTO와의 차이**는 7-06에서 다뤘다. 한 줄로 **CTO는 밖에 파는 것, CIO는 안에서 쓰는 것**이다.

**QA 접점 — 사내 시스템 도입의 사용자 인수 테스트(UAT)**

사내 시스템은 **사용자가 동료**다. 테스트 설계보다 **현업 사용자를 테스트에 참여시키는 운영**이 핵심이다.

| 항목 | 내용 |
|---|---|
| 누가 테스트하나 | 실제 업무 담당자 (회계팀, 인사팀) — QA는 설계와 진행 |
| 무엇으로 | 기능 목록이 아니라 **업무 시나리오** ("월말 경비 마감") |
| 합격 기준 | 사전에 합의한 필수 시나리오 통과율, 치명 결함 0건 |
| 기록 | 시나리오별 결과와 **현업 확인 서명** |
| 연동 | 결제 → 회계 전표처럼 **시스템 사이 데이터 정합성** (트랙 2-05) |

### CDO — 디지털 전환(DX)을 이끄는 사람

**Chief Digital Officer.** 오프라인·수작업 중심의 사업 방식을 디지털로 바꾼다. 금융·제조·유통 같은 **전통 산업에서 특히 흔한 직함**이다.

| DX 예 | 전 | 후 |
|---|---|---|
| 신청 절차 | 종이 신청서, 창구 방문 | 모바일 앱 신청 |
| 주문 | 매장·전화 | 온라인·앱 주문 |
| 내부 업무 | 엑셀·수기 결재 | 워크플로 시스템 |

CDO가 보는 숫자: 디지털 채널 매출 비중, 디지털 채널 이용률, 전환 과제 진척.

**DX 프로젝트에서 QA가 특히 볼 것**

| 리스크 | 이유 | QA의 대응 |
|---|---|---|
| **암묵적 업무 규칙** | 기존 담당자의 머릿속에만 있는 예외 처리 | 현업 인터뷰로 규칙을 끌어내 결정테이블로 (트랙 1-03) |
| 병행 운영 기간 불일치 | 종이·기존 시스템과 새 시스템이 동시에 돈다 | 양쪽 데이터 대사 쿼리 |
| 디지털 소외 사용자 | 고령층, 저사양 기기 | 접근성, 글자 크기, 느린 네트워크 테스트 |
| 기존 데이터 이관 | 수십 년 치 형식이 제각각 | 이관 전후 건수·합계 검증 |

### 또 하나의 CDO — Chief Data Officer

같은 약어로 **데이터 책임자**를 뜻하기도 한다(7-01). 데이터 거버넌스, 데이터 품질, 데이터 활용, 개인정보·윤리를 맡는다.

| | Chief Digital Officer | Chief Data Officer |
|---|---|---|
| 핵심 | 디지털로 사업 방식 전환 | 데이터를 믿고 쓸 수 있게 |
| QA 접점 | DX 프로젝트 품질 | **데이터 품질** 검증 |

데이터 품질은 흔히 이런 차원으로 본다.

| 차원 | 질문 | 7-07 사례와의 연결 |
|---|---|---|
| 정확성 | 값이 사실과 맞는가 | |
| 완전성 | 필수값이 비어 있지 않은가 | |
| 일관성 | 시스템 간 같은 값인가 | 주문 금액 = 결제 금액 |
| 적시성 | 제때 들어오는가 | 대시보드 지연 |
| 유일성 | 중복이 없는가 | **가입 이벤트 두 번 기록 (사례 C)** |

## 왜 채용시장이 요구하는가

- 핀테크·커머스·헬스케어 공고에 **"보안 테스트 기본 이해(OWASP)", "개인정보 처리 이해"** 가 자주 들어간다.
- ISMS·ISMS-P 인증 기업은 **테스트 증적 관리 경험**을 우대한다.
- 금융·제조·SI의 **DX 프로젝트 QA** 는 UAT 진행과 현업 커뮤니케이션 능력을 본다.
- **데이터 QA·데이터 품질** 직무가 따로 생기고 있다. 트랙 2의 SQL이 여기서 쓰인다.
- 면접 질문: **"테스트에 운영 데이터를 써야 한다면 어떻게 하시겠습니까?"** — 승인·모니터링·삭제로 답하면 된다.

## 실습 과제

### 과제 1 — 결함 리포트 첨부물 점검 (15분)

최근 결함 리포트 10건(본인 것 또는 공개 이슈 트래커)의 첨부물을 점검한다.

| 리포트 | 첨부 종류 | 개인정보 | 토큰·쿠키 | 조치 필요 |
|---|---|---|---|---|
| | | | | |

**한 건이라도 나오면** 팀의 결함 리포트 템플릿에 "첨부물 개인정보 확인" 항목을 추가하자고 제안한다.

### 과제 2 — 보안 결함 보고서 작성 (15분)

7-07 사례 B(전각 전화번호 → 500 오류 + 로그 평문 기록)를 위 **제한 채널 보고 템플릿**으로 작성한다.

- 운영 반영 여부를 **"확인됨/미확인"** 으로 명확히 쓴다
- 재현 절차는 보고서 본문이 아니라 제한된 첨부로 분리한다

### 과제 3 — 테스트 데이터 정책 초안 (15분)

팀에 제안할 1쪽짜리 정책을 쓴다.

```text
1. 기본 원칙      합성 데이터 우선, 운영 데이터 사용은 예외
2. 예외 절차      승인자(CISO/CPO), 사용 범위, 기간
3. 보관           어디에, 누가 접근, 암호화
4. 삭제           시험 종료 후 N일 이내, 삭제 기록
5. 첨부물         스크린샷·로그 마스킹 규칙
6. AI 도구        운영 데이터 입력 금지
```

### 과제 4 — 사내 시스템 UAT 시나리오 (15분)

"경비 정산 SaaS 도입" 을 가정하고 UAT 시나리오 5개를 쓴다.

### 과제 5 — 데이터 품질 점검 쿼리 (15분)

[db-fiddle](https://www.db-fiddle.com) 에 간단한 테이블을 만들고 차원별 쿼리를 실행한다. (트랙 2-05 연결)

```sql
-- 완전성: 필수값 누락
SELECT COUNT(*) FROM users WHERE email IS NULL OR phone IS NULL;

-- 유일성: 가입 완료 이벤트 중복 (7-07 사례 C)
SELECT user_id, COUNT(*) AS cnt
FROM events
WHERE event_name = 'sign_up_complete'
GROUP BY user_id
HAVING COUNT(*) > 1;

-- 일관성: 주문 금액과 결제 금액 불일치
SELECT o.id, o.total_amount, p.amount
FROM orders o
JOIN payments p ON p.order_id = o.id
WHERE o.total_amount <> p.amount;

-- 적시성: 마지막 이벤트 적재 시각
SELECT MAX(created_at) FROM events;
```

### 과제 6 — AI 결과 검증 (10분)

AI 실습 도우미에 요청한다.

> 직원 80명, 연매출 300억원 규모의 온라인 쇼핑몰은 정보보호 최고책임자(CISO)를 지정하고 신고해야 하는가? 근거 조항과 함께 설명하라.

| 확인 항목 | 결과 |
|---|---|
| 정보통신망법 제45조의3을 근거로 들었는가 | |
| 신고 면제·겸직 제한 기준을 **단정하지 않고** 확인 필요로 표시했는가 | |
| CISO와 개인정보 보호책임자를 혼동하지 않았는가 | |
| 존재하지 않는 조항·금액을 만들어내지 않았는가 | |
| 원문(국가법령정보센터, 과기정통부 안내) 확인을 권했는가 | |

## 자가 체크리스트

- [ ] CISO·CIO·CDO의 책임을 한 줄씩 구분해 말할 수 있다
- [ ] 정보통신망법상 CISO 업무 4가지를 안다
- [ ] CISO 지정·신고가 정보통신망법 제45조의3의 의무임을 안다
- [ ] 겸직 제한 대상 기준(자산총액 5조원, ISMS 의무대상 중 5천억원)을 안다
- [ ] CISO와 개인정보 보호책임자(CPO)의 근거 법과 범위를 구분한다
- [ ] 보안 결함은 제한 채널로 즉시 보고하고 운영에서 재현하지 않음을 안다
- [ ] 보안 결함 보고에 영향 데이터·노출 범위·운영 반영 여부를 넣을 수 있다
- [ ] ISMS-P 2.8.3·2.8.4가 QA 업무와 어떻게 연결되는지 설명할 수 있다
- [ ] 결함 리포트 첨부물이 개인정보 유출 경로가 될 수 있음을 안다
- [ ] 테스트 기록이 인증 심사 증적이 됨을 안다
- [ ] 사내 시스템 UAT를 업무 시나리오와 현업 참여로 설계할 수 있다
- [ ] DX 프로젝트의 암묵적 업무 규칙 리스크를 설명할 수 있다
- [ ] Chief Digital Officer와 Chief Data Officer를 구분하고 데이터 품질 5차원을 안다
