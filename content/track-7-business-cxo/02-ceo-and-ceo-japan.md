## 개념 설명

### CEO — 모든 업무를 총괄하고 최종 결정을 내린다

"총괄" 은 추상적이다. CEO가 실제로 하는 일로 쪼개 본다.

| 하는 일 | 설명 | QA와의 접점 |
|---|---|---|
| 방향 설정 | 무엇을 하고 **무엇을 안 할지** 정한다 | 품질 목표가 회사 목표에 들어 있는가 |
| 자원 배분 | 사람·돈·시간을 어디에 쓸지 | QA 인력, 자동화 투자 |
| 최종 결정 | 임원 의견이 갈릴 때 결론을 낸다 | 릴리즈 Go/No-Go 에스컬레이션 |
| 이사회·주주 보고 | 성과와 리스크를 설명한다 | 대형 장애·보안 사고 보고 |
| 위기 대응 | 대외 메시지와 책임 | 장애 공지, 사후 보고 |

### CEO는 "품질 vs 일정" 이 아니라 "무엇을 잃는가" 로 결정한다

```text
QA가 흔히 올리는 보고:  "결제 결함 3건 미해결입니다. 배포에 반대합니다."
CEO가 듣고 싶은 것:     "오늘 배포하면 무엇을 잃고, 늦추면 무엇을 잃는가. 선택지는?"
```

CEO는 품질을 싫어하지 않는다. **품질 외에도 저울에 올라가는 것이 많을 뿐이다** — 계약한 출시일, 경쟁사 일정, 마케팅 비용, 투자자 약속.

그래서 CEO에게 가는 보고에는 네 가지가 있어야 한다. (트랙 1-07 Go/No-Go 판단과 이어진다)

| 요소 | 예 |
|---|---|
| **결론 한 문장** | "결제수단 하나를 빼고 예정대로 출시하는 것을 권고합니다" |
| **선택지 2~3개와 각각의 리스크** | 그대로 출시 / 부분 출시 / 1주 연기 |
| **사실과 추정의 구분** | "재현 100%" 는 사실, "매출 영향 월 N억" 은 추정 |
| **필요한 결정과 기한** | "오늘 18시까지 옵션 선택이 필요합니다" |

**QA는 결정권자가 아니라 결정에 필요한 정보를 가장 정확히 가진 사람이다.** "반대합니다" 보다 "이 선택지는 이런 리스크가 있습니다" 가 더 강하다.

### 대표이사와 CEO, 代表取締役와 社長

| | 법적 지위 (등기) | 직함 (호칭) |
|---|---|---|
| 한국 | 대표이사 | CEO, 사장, 대표 |
| 일본 | 代表取締役 (다이효토리시마리야쿠) | 社長, CEO |

일본에서는 법적 대표(代表取締役)와 직함(社長)을 한 사람이 겸해 **"代表取締役社長"** 이라고 쓰는 경우가 대부분이다.
외국계 기업의 일본 법인장은 **Country Manager**, **General Manager Japan**, **CEO Japan** 등 다양한 이름으로 불린다.

### CEO Japan — 일본 지역의 사업과 법인을 이끄는 최고책임자

글로벌 기업이 일본에 진출하는 형태에 따라 "CEO Japan" 이 책임지는 범위가 달라진다.

| 진출 형태 | 일본어 | 특징 | 책임자 |
|---|---|---|---|
| **현지 법인(자회사)** | 日本法人 (株式会社, 合同会社 등) | 본사와 **별도 법인**. 계약·채용·세무를 독립적으로 한다 | 代表取締役 (= 흔히 CEO Japan) |
| **지점** | 外国会社の日本支店 | 본사와 **같은 법인**. 영업은 할 수 있지만 법적 책임은 본사에 있다 | 日本における代表者 |
| **연락사무소** | 駐在員事務所 | 시장조사·연락 같은 준비 활동만. **영업활동은 할 수 없다** | 소장 |

알아두면 좋은 사실.

- 2015년 3월 일본 법무성 통지로, **일본 주식회사의 대표이사 전원이 해외 거주자여도 설립 등기가 가능**해졌다. 그 전에는 최소 1명이 일본에 주소가 있어야 했다.
- 반면 외국회사가 일본에서 거래를 계속하려면 **日本における代表者** 를 두어야 하고, 그중 1명 이상은 일본에 주소가 있어야 한다.

즉 CEO Japan이 **현지에 상주하지 않는 구조도 법적으로 가능**하다. 그래서 "일본 결정은 누가, 어디서 하는가" 를 확인해야 한다.

### "독립적으로 이끈다" 의 실제 모습 — 매트릭스 조직

```text
                  본사 CEO / 아시아태평양 총괄
                            │  (실선: 일본 사업 성과 보고)
                        CEO Japan
            ┌───────────────┼───────────────┐
        일본 영업        일본 마케팅        일본 CS
            ┊                ┊                ┊   (점선: 기능별 가이드)
       Global CRO       Global CMO       Global CCO
```

지역 조직(CEO Japan)과 기능 조직(본사 CMO 등)이 **겹친다.** 이게 매트릭스 조직이다.

| 충돌 상황 | 흔한 질문 |
|---|---|
| 본사는 글로벌 동시 출시를 원하고, 일본은 현지화 미완료로 연기를 원한다 | 출시일 결정권은 본사 CPO인가, CEO Japan인가 |
| 본사 디자인 시스템이 일본 주소 입력 방식과 맞지 않는다 | 예외를 누가 승인하는가 |
| 일본에서만 발생하는 결함 | 일본 QA가 막을 수 있는가, 본사 릴리즈 트레인을 따라야 하는가 |

**이 질문들은 결함이 나오기 전에 물어봐야 한다.** 출시 D-1에 결정권자를 찾으면 늦다.

### CEO Japan이 책임지는 숫자

| 숫자 | QA 관점 |
|---|---|
| 일본 매출·손익(P&L) | 일본에서만 쓰는 결제·가격 기능의 결함 |
| 현지 고객 만족·평판 | 번역·표기 오류, 앱 리뷰 |
| 현지 법규 준수 | 개인정보(個人情報保護法), 통신판매 표기(特定商取引法), 가격 표시 |
| 본사와의 우선순위 조정 | 일본 전용 결함이 글로벌 백로그에서 밀리지 않게 근거 제공 |

### CEO Japan이 QA에게 기대하는 것 — 일본 출시 품질 체크포인트

현지 출시에서 **번역·표기 오류는 기능 결함과 같은 무게로 다뤄지는 경우가 많다.** 신뢰의 문제이기 때문이다.

| 영역 | 확인 항목 | 흔한 결함 |
|---|---|---|
| 문자 | 全角(전각)/半角(반각) 입력 모두 허용·정규화 | 전각 숫자 전화번호 입력 시 검증 실패, 서버 오류 |
| 이름 | 姓/名 순서, **フリガナ**(이름 읽기, 가타카나) 필드 | 영문식 First/Last 순서, フリガナ 없음 |
| 주소 | **郵便番号 7자리**(123-4567) → 주소 자동입력, 都道府県 → 市区町村 → 番地 순서 | 우편번호 5자리 검증, 한국식 주소 순서 |
| 날짜 | 西暦·和暦(令和) 병기, 年月日 형식 | 날짜 포맷 깨짐, 생년월일 선택기 불편 |
| 통화·가격 | 円은 소수점 없음, 소비자 대상 가격은 **세금 포함 총액 표시** | `¥1,000.00`, 세전 가격만 표시 |
| 결제 | 신용카드 외 **コンビニ決済(편의점 결제)**, 銀行振込, 後払い | 입금 대기 같은 비동기 상태 미처리 (트랙 1-03 상태전이) |
| 문구 | です/ます 체 경어, 자연스러운 표현 | 직역 티, 반말, 긴 문장으로 레이아웃 깨짐 |
| 법정 표기 | 特定商取引法に基づく表記, 個人情報の取扱い 페이지 | 페이지 누락, 사업자 정보 미기재 |
| 문자 인코딩 | 이체자(髙, 﨑 등), 이모지 | 레거시 연동(Shift_JIS)에서 글자 깨짐 |

**편의점 결제는 상태전이 테스트의 좋은 예다.** 주문 → 결제번호 발급 → (며칠 뒤) 입금 → 주문 확정 / 기한 초과 → 자동 취소. 신용카드만 테스트하면 **입금 대기** 상태를 통째로 놓친다.

## 왜 채용시장이 요구하는가

- 일본 진출을 한 한국 IT 기업이 많고, **현지화(로컬라이제이션) QA**, **일본어 가능 QA** 공고가 꾸준하다.
- 매트릭스 조직에서 **결정권자를 모르면 결함이 공중에 뜬다.** 이걸 먼저 정리하는 QA는 리드 역할을 맡게 된다.
- Go/No-Go를 **선택지와 리스크로 보고한 경험**은 시니어 면접의 단골 질문이다.
- 해외 출시 경험은 이력서에서 **"비즈니스 영향이 큰 릴리즈를 다뤄봤다"** 는 신호가 된다.

## 실습 과제

### 과제 1 — CEO용 1장 보고 (15분)

트랙 1-07에서 다룬 릴리즈 판단 사례(또는 본인의 실제 경험)로 아래를 채운다.

```text
[결정 요청]  무엇을 / 언제까지
[결론]      권고안 한 문장
[선택지]    1) ...  리스크: ...
            2) ...  리스크: ...
            3) ...  리스크: ...
[사실]      재현율, 영향 범위(확인된 것만)
[추정]      매출·고객 영향 (근거와 범위)
```

**"반대합니다"·"찬성합니다" 라는 단어 없이** 쓴다.

### 과제 2 — 일본 출시용 현지화 TC 20건 (20분)

회원가입 + 결제 흐름을 대상으로 위 체크포인트 표에서 TC를 뽑는다.

| # | 영역 | 입력/조건 | 기대 결과 |
|---|---|---|---|
| 1 | 문자 | 전화번호에 전각 숫자 `０９０１２３４５６７８` | 반각으로 정규화되어 저장 |
| ... | | | |

**경계값(트랙 1-02)** 도 섞는다 — 우편번호 6자리·8자리, フリガナ에 히라가나 입력.

### 과제 3 — 매트릭스 결정권 질문지 (10분)

일본 출시를 앞둔 팀이라고 가정하고, **결함이 나오기 전에** 물어볼 질문 5개를 쓴다.

```text
1. 일본 전용 결함으로 출시를 연기할 권한은 누구에게 있는가?
2. ...
```

### 과제 4 — 일본 서비스 관찰 (15분)

일본의 대형 쇼핑몰이나 서비스 한 곳에서 **회원가입 폼과 결제 선택 화면**을 관찰한다. (실제 가입·결제는 하지 않는다)

| 관찰 항목 | 기록 |
|---|---|
| フリガナ 필드가 있는가 | |
| 우편번호 입력 시 주소가 자동으로 채워지는가 | |
| 전각 숫자를 넣으면 어떻게 되는가 | |
| 결제수단 종류 | |
| 가격 표시가 세금 포함인가 | |

### 과제 5 — AI 결과 검증 (10분)

AI 실습 도우미에 요청한다.

> 한국 서비스를 일본에 출시할 때 회원가입과 결제에 필요한 현지화 테스트 케이스를 작성하라.

| 확인 항목 | 결과 |
|---|---|
| 전각/반각 입력 케이스가 있는가 | |
| フリガナ, 우편번호 7자리·자동입력이 있는가 | |
| 편의점 결제의 **입금 대기 → 확정/만료** 상태가 있는가 | |
| 세금 포함 가격 표시 확인이 있는가 | |
| 확인할 수 없는 법 조항을 단정적으로 쓰지 않았는가 | |

## 자가 체크리스트

- [ ] CEO가 실제로 하는 일 5가지를 말할 수 있다
- [ ] CEO가 "품질 vs 일정" 이 아니라 "무엇을 잃는가" 로 결정함을 이해한다
- [ ] CEO 보고에 필요한 4요소(결론·선택지·사실/추정·결정 기한)를 안다
- [ ] QA가 결정권자가 아니라 정보 제공자임을 설명할 수 있다
- [ ] 대표이사·代表取締役(법적 지위)과 CEO·社長(직함)을 구분한다
- [ ] 현지 법인·지점·연락사무소의 차이를 설명할 수 있다
- [ ] 일본 법인 대표이사 전원이 해외 거주여도 된다는 2015년 변경을 안다
- [ ] 매트릭스 조직에서 지역 조직과 기능 조직이 충돌하는 상황을 예로 들 수 있다
- [ ] 출시 전에 결정권자를 확인해야 하는 이유를 안다
- [ ] 일본 현지화 체크포인트(전각/반각, フリガナ, 우편번호, 세금 포함 가격 등)를 5개 이상 안다
- [ ] 편의점 결제를 상태전이 테스트로 설계할 수 있다
