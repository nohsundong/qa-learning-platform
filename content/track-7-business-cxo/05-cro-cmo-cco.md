## 개념 설명

### 세 사람은 같은 여정의 다른 구간을, 다른 숫자로 본다

```text
 인지 ─→ 관심·탐색 ─→ 가입·구매 ─→ 온보딩 ─→ 사용·재구매 ─→ 갱신·추천

 └───── CMO ─────┘
          └────────── CRO (매출이 생기는 구간의 영업·마케팅·CS 조율) ─────────┘
 └──────────────── CCO (고객 여정 전체의 경험 + 성장) ──────────────────────┘
```

| | 핵심 질문 | 대표 숫자 |
|---|---|---|
| **CMO** | 우리를 알고 찾아오게 하려면? | 유입, 고객획득비용(CAC), 광고수익률(ROAS), 브랜드 인지도 |
| **CRO** | 매출이 예측 가능하게 커지려면? | 파이프라인, 단계별 전환율, 매출 달성률, ARR, 순매출유지율(NRR) |
| **CCO** | 고객이 막힘없이 가치를 느끼고 남으려면? | 활성화율, 리텐션, 이탈률, NPS, CSAT, 고객생애가치(CLTV) |

실제로는 겹친다. **회사마다 경계가 다르므로** 누가 어느 숫자를 가졌는지 확인하는 것이 먼저다.

### CRO — 영업과 마케팅 등을 조율해 전체 매출과 수익을 극대화

비교적 최근에 널리 퍼진 직함이다. 마케팅·영업·고객성공이 **각자 자기 숫자만 보다가 매출이 새는 문제**를 한 사람이 묶어서 보게 한다.

| 하는 일 | 설명 |
|---|---|
| 매출 조직 조율 | 마케팅 → 영업 → 고객성공으로 넘어가는 이음매 관리 |
| 매출 예측 | 분기·연간 예측과 정확도 |
| 가격·패키지 | 요금제, 할인 정책 (제품·재무와 협의) |
| **RevOps** (Revenue Operations) | 매출 조직의 도구·프로세스·데이터를 통합 운영. 보통 CRO 산하 |

**Chief Sales Officer와의 차이** — Sales Officer는 영업팀의 목표 달성·영업 프로세스에 집중하고, CRO는 영업을 포함한 **매출 전 구간**을 본다.

**QA 접점**

| 영역 | 검증 포인트 |
|---|---|
| 매출 경로 기능 | 가입, 결제, 요금제 변경, 쿠폰, 자동 갱신 |
| 가격 정책 | 조건이 얽힌 할인 → 결정테이블 (트랙 1-03) |
| CRM·결제 연동 | 결제 시스템과 CRM의 금액·상태 일치 → 정합성 쿼리 (트랙 2-05) |
| RevOps 데이터 | 매출 예측이 틀린 데이터로 계산되지 않는가 |

### CMO — 브랜드 가치를 높이고 제품을 알리는 마케팅 전략

| 하는 일 | QA 접점 |
|---|---|
| 캠페인 기획·집행 | 랜딩 페이지, 프로모션 코드의 경계값(기간·횟수·금액) |
| 대규모 이벤트 | **트래픽 급증 → 사전 성능 테스트** (트랙 5) |
| 퍼포먼스 마케팅 | **트래킹 이벤트·UTM 파라미터가 정확히 기록되는가** |
| CRM 마케팅 (푸시·메일) | 수신 동의한 사람에게만 가는가, 링크·딥링크가 동작하는가 |

**트래킹 검증은 QA가 가장 자주 놓치는 영역이다.** 화면은 멀쩡한데 구매 완료 이벤트가 두 번 찍히면, 마케팅은 **틀린 숫자로 예산을 배분**한다. 사용자에게는 안 보이는 결함이지만 의사결정에는 치명적이다.

광고성 메시지는 법적 요건도 있다. 한국 정보통신망법은 **영리 목적 광고성 정보를 보낼 때 수신자의 사전 동의**를 요구한다(제50조). 수신 거부한 사용자에게 푸시가 가면 기능 결함이자 규제 리스크다.

### CCO — 고객 여정 전체를 관리하고 성장을 도모

위 목록의 CCO는 **Chief Customer Journey & Growth Officer** 다. 두 전통을 합친 역할로 이해하면 된다.

| 전통적 Chief Customer Officer | + Growth(그로스) |
|---|---|
| 구매 이후 만족·유지·충성도 | 첫 접점부터 전환·활성화·확장까지 실험으로 성장 |
| 고객성공(CS)·지원 조직 리드 | 퍼널 분석, A/B 테스트, 온보딩 개선 |
| NPS, CSAT, 이탈률, NRR | 활성화율, 리텐션 곡선, 바이럴 계수 |

**고객 여정 지도(Customer Journey Map)** 는 CCO의 기본 도구다.

| 단계 | 고객 행동 | 접점 | 감정 | 불편 지점 |
|---|---|---|---|---|
| 인지 | 광고를 본다 | SNS 광고 | 궁금 | |
| 가입 | 이메일로 가입 | 앱 | 기대 | **인증 메일이 5분 늦게 옴** |
| 온보딩 | 첫 설정 | 튜토리얼 | 혼란 | 건너뛰기 버튼 없음 |
| 구매 | 쿠폰으로 결제 | 결제 페이지 | 불안 | 쿠폰 적용 후 금액 갱신 느림 |
| 재구매 | 다시 방문 | 푸시 | 만족/불만 | 딥링크가 홈으로만 감 |

**불편 지점 칸의 절반은 QA가 채울 수 있는 결함이다.**

그로스 조직에서 쓰는 **AARRR**(Acquisition·Activation·Retention·Referral·Revenue) 퍼널도 같은 여정을 숫자로 본 것이다.

### 고객 지표 용어 정리

| 지표 | 뜻 | 계산/기준 |
|---|---|---|
| 전환율 | 다음 단계로 넘어간 비율 | 결제 완료 ÷ 결제 페이지 도달 |
| 활성화율 | 핵심 가치를 처음 경험한 비율 | 회사가 정의 (예: 첫 주문 완료) |
| 리텐션 (D1/D7/D30) | N일 뒤에도 돌아온 비율 | 코호트별 |
| 이탈률 (Churn) | 떠난 고객 비율 | 기간 내 해지 ÷ 기간 시작 고객 |
| **NPS** | 추천 의향 | 0~10점 중 9~10점(추천자) % − 0~6점(비추천자) % |
| CSAT | 특정 경험 만족도 | "이번 상담에 만족하셨나요?" |
| GRR / NRR | 기존 고객 매출 유지율 (확장 제외/포함) | 구독 사업에서 중요 |
| CLTV | 고객 한 명이 평생 가져오는 가치 | CAC와 비교 |

### 결함을 여정과 매출로 환산하기

심각도(Severity)는 기술적 영향, 우선순위(Priority)는 비즈니스 영향이다(트랙 1-06). **우선순위를 숫자로 말하는 방법**이 이것이다.

```text
결함: iOS 앱 특정 버전에서 쿠폰 적용 후 결제 버튼이 비활성화된다

① 여정 단계       구매 (결제)
② 단계 도달       결제 페이지 일 20,000명 (분석 도구 실측)
③ 영향 범위       해당 iOS 버전 30% × 쿠폰 사용 25% = 7.5% → 일 1,500명
④ 이탈 추정       다른 방법으로 결제하지 못하고 떠나는 비율 60% → 일 900명
⑤ 금액           평균 주문 금액 35,000원 → 일 약 3,150만원 매출 손실 (추정)
```

**④는 추정이므로 범위로 말한다.**

| 이탈 가정 | 이탈 인원/일 | 매출 영향/일 |
|---|---|---|
| 40% | 600명 | 약 2,100만원 |
| 60% | 900명 | 약 3,150만원 |
| 80% | 1,200명 | 약 4,200만원 |

같은 결함을 **받는 사람에 따라 다르게 강조**한다.

| 대상 | 강조할 것 |
|---|---|
| CRO | 일 매출 영향 2,100만~4,200만원, 핫픽스까지 누적액 |
| CCO | 일 1,500명의 결제 실패 경험, **쿠폰을 쓰는 충성 고객층**에 집중, 리뷰·문의 증가 |
| CMO | 진행 중인 캠페인 쿠폰이면 → 캠페인 일시 중단·연장 판단 필요 |

### 기능 목록이 아니라 여정으로 테스트하기

| 기능 중심 | 여정 중심 |
|---|---|
| "쿠폰 적용 API 테스트" | "광고 클릭 → 가입 → 첫 구매 쿠폰 적용 → 결제 완료 → 구매 이벤트 기록" |
| 기능마다 따로 통과 | **이음매**(인증 메일 지연, 딥링크, 세션 만료)에서 실패를 찾는다 |

VOC(고객의 소리)는 **여정 기반 테스트 케이스의 원천**이다. CS 문의 상위 10개 유형을 회귀 테스트에 넣는 것만으로도 CCO와 대화할 거리가 생긴다.

## 왜 채용시장이 요구하는가

- 커머스·핀테크·SaaS 공고에 **"비즈니스 임팩트 기반 우선순위 판단"** 이 늘고 있다. 결함을 금액·고객 수로 말하는 능력이다.
- 그로스 조직의 **A/B 테스트·실험 플랫폼 QA**, **데이터 트래킹 QA** 는 별도 직무로 뽑기도 한다.
- 면접 질문: **"같은 날 결함 두 개가 나오면 무엇부터 고치자고 하겠습니까?"** — 여정 단계와 영향 규모로 답한다.
- VOC를 테스트로 연결한 경험은 **고객 중심 QA** 라는 강한 인상을 준다.

## 실습 과제

### 과제 1 — 여정 지도 + 결함 매핑 (20분)

자주 쓰는 서비스 하나로 6단계 여정 지도를 그리고, **본인이 겪은 불편·결함**을 단계에 배치한다.

| 단계 | 고객 행동 | 접점 | 불편·결함 | 책임자(CMO/CRO/CCO) |
|---|---|---|---|---|
| | | | | |

### 과제 2 — 결함 매출 환산 (15분)

본인이 본 결함(또는 가상 결함) 하나를 ①~⑤ 단계로 환산한다.

1. 가정마다 **출처**를 적는다 (실측/업계 자료/추정)
2. 이탈 가정을 **3단계 범위**로 계산한다
3. CRO·CCO·CMO 각각에게 보낼 **한 줄**을 쓴다

### 과제 3 — 트래킹 이벤트 관찰 (15분)

**본인이 운영하거나 테스트 권한이 있는 사이트**에서 개발자도구 Network 탭을 연다.

1. 분석 도구 요청을 찾는다 (예: Google Analytics 4는 `collect` 요청)
2. 페이지 이동, 버튼 클릭, 가입 완료 때 이벤트가 **몇 번** 전송되는지 기록
3. 새로고침·뒤로가기 후 **중복 전송**되는지 확인

| 행동 | 기대 이벤트 | 실제 전송 횟수 | 판정 |
|---|---|---|---|
| | | | |

### 과제 4 — 캠페인 사전 점검표 (10분)

"다음 주 월요일 오전 10시, 전 회원 대상 50% 할인 쿠폰 푸시" 를 앞두고 QA 체크리스트 10개를 만든다.
**성능(트랙 5), 경계값(트랙 1-02), 수신 동의, 트래킹** 이 모두 들어가야 한다.

### 과제 5 — AI 결과 검증 (10분)

AI 실습 도우미에 요청한다.

> 결제 페이지 결함이 매출에 미치는 영향을 추정하는 방법과 예시 계산을 보여라.

| 확인 항목 | 결과 |
|---|---|
| 가정을 단계별로 분리했는가 | |
| 영향 범위(비율)를 곱했는가, 전체 트래픽에 바로 곱하지 않았는가 | |
| 추정치를 **범위**로 제시했는가 | |
| 산수를 직접 다시 계산하면 맞는가 | |
| 매출 외 영향(고객 경험, 지표 왜곡)을 언급했는가 | |

## 자가 체크리스트

- [ ] CMO·CRO·CCO가 고객 여정의 어느 구간을 보는지 그릴 수 있다
- [ ] 세 역할의 대표 숫자를 각각 2개 이상 말할 수 있다
- [ ] CRO와 Chief Sales Officer의 차이를 설명할 수 있다
- [ ] RevOps가 무엇이고 QA와 어떻게 연결되는지 안다
- [ ] 트래킹 이벤트 결함이 마케팅 의사결정을 왜곡한다는 것을 설명할 수 있다
- [ ] 광고성 메시지 수신 동의가 기능 검증 대상임을 안다
- [ ] Chief Customer Journey & Growth Officer가 전통적 CCO와 그로스를 합친 역할임을 안다
- [ ] 고객 여정 지도의 구성(단계·행동·접점·감정·불편)을 안다
- [ ] NPS 계산 방법(9~10점 % − 0~6점 %)을 안다
- [ ] 결함을 여정 단계 → 도달 → 영향 범위 → 이탈 → 금액으로 환산할 수 있다
- [ ] 추정치를 범위로 제시할 수 있다
- [ ] 같은 결함을 CRO·CCO·CMO에게 다르게 강조할 수 있다
- [ ] 기능 중심 테스트와 여정 중심 테스트의 차이를 설명할 수 있다
