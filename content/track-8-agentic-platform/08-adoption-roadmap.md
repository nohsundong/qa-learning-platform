## 개념 설명

### 성숙도 — 수동에서 다크 테스팅 팩토리까지

웨비나의 로드맵 그림과 UiPath 자료를 합치면 다섯 단계다.

| 단계 | 모습 | 사람 | 스크립트 | 에이전트 |
|---|---|---|---|---|
| 1. 수동 | 사람이 실행 | ●●● | | |
| 2. 자동화 | 사람이 스크립트를 쓰고 도구가 실행 | ●● | ●● | |
| 3. AI 증강 | AI가 생성·분석을 돕고 사람이 조종 | ●● | ●● | ● |
| 4. 자율 (좁은 작업) | 에이전트가 정해진 작업을 스스로 수행 | ● | ●● | ●● |
| 5. 다크 테스팅 팩토리 | 24시간 스스로 계획·설계·실행·유지, 사람은 방향과 예외 | ○ | ● | ●●● |

**다크 테스팅 팩토리**는 공장의 불 꺼진 생산 라인(lights-out manufacturing)에서 온 말이다. UiPath 설명의 요점:

- 에이전트·자동화가 맡는 것: 변경 발견, 테스트 설계·실행, 실패 분류, 깨진 스크립트 치유, 이슈 라우팅
- 사람이 정하는 것: **허용 가능한 리스크, 승인 요건, 릴리즈별 완료 정의, 에스컬레이션 조건**
- 테스터를 대체하지 않고 **실행에서 품질 리더십으로** 역할을 옮긴다

웨비나 발표: 다크 테스팅 팩토리 개념을 **다음 해 1분기에 제품으로 출시 예정**(로드맵). 도입 계획에 넣을 때는 출시 여부를 다시 확인한다.

**건너뛰기는 없다.** 2단계의 안정적인 스크립트 자산과 8-04의 결정 테이블 없이 5단계로 가면 사고가 난다.

### 시작점 — UiPath가 권하는 첫걸음

```text
1. 반복 유지보수가 많은 영역을 찾는다   (SAP 프로세스, 웹 플로, 회귀 스위트)
2. 이미 자동으로 돌아가는 곳을 파악한다
3. 에스컬레이션 소유자를 명확히 한다    (누가 받고, 누가 결정하나)
4. 결정을 기록해 반복 개선한다
```

3번이 가장 자주 빠진다. **사람에게 넘기는 경로의 주인이 없으면 에이전트 결과는 쌓이기만 한다.**

### 애널리스트 리포트 읽는 법

웨비나는 "3대 애널리스트가 동시에 리더로 지정한 소수 벤더"라고 강조했다. 확인한 사실은 이렇다.

| 리포트 | 확인한 내용 | 같은 리포트의 다른 리더 |
|---|---|---|
| **Gartner Magic Quadrant for AI-Augmented Software Testing Tools** | 2025년 10월 첫 발행, UiPath Leader | Tricentis, Keysight, OpenText 등 |
| **Forrester Wave: Autonomous Testing Platforms, Q4 2025** | 15개 벤더 평가, UiPath Leader (2025-12 발표) | ACCELQ, Keysight, Tricentis 등 |
| **IDC MarketScape: Worldwide Cloud Testing** | UiPath Leader — **공개 자료로 확인한 것은 2022년판** | — |

읽을 때 체크할 것:

```text
□ 리더는 한 곳이 아니다 — 같은 리포트에 여러 리더가 있다
□ 발행 연도와 시장 정의를 확인한다 (클라우드 테스팅 ≠ 자율 테스팅 플랫폼)
□ 평가 기준의 가중치가 우리 우선순위와 같은가 (SAP 지원이 중요한 조직 vs 모바일 중심 조직)
□ 무료로 배포되는 사본은 대개 해당 벤더가 배포권을 산 것이다 — 불리한 부분은 요약에서 빠질 수 있다
□ 리포트는 후보를 줄이는 도구다. 선택은 우리 PoC가 한다
```

### 고객 사례 수치 검증

**공개 자료로 확인한 수치**

| 출처 | 내용 |
|---|---|
| Test Cloud 출시 발표 (2025-03) | Cisco — Autopilot으로 **수동 테스트 노력을 거의 절반으로** 감축 |
| 같은 발표에 인용된 IDC 조사 | 테스트 효율 36% 향상, 장애 50% 감소, 문제 해결 시간 93% 단축, 신기능 제공 처리량 2배 |
| UiPath 제품 페이지 | State Street 테스트 실행 시간 67% 단축 · NatWest 테스트 유지보수 비용 75% 절감 · EDF Renewables SAP 워크로드 자동화 커버리지 90% |

**웨비나에서 소개됐지만 이번 조사에서 원자료를 찾지 못한 수치**

- 글로벌 기업 사례: 6개월 만에 테스트 자동화율 95% (오토파일럿 초안 + 오브젝트 리포지토리 재사용 강제)
- Micron: 스프린트 회귀 주기를 수 주에서 수 시간으로 (테스트 생성과 환경 준비를 병렬화해 대기 제거)
- PepsiCo: HR 채용~온보딩 다중 페르소나 회귀 테스트 소요 시간 80% 이상 단축

찾지 못했다고 틀린 것은 아니다. **도입 검토에 쓰려면 원자료를 요청한다.** 질문은 수치마다 같다.

```text
□ 기준선(Before)은 무엇이고 언제 측정했나
□ 측정 기간과 대상 범위(앱·테스트 수)는
□ "자동화율" 의 분모는 무엇인가 (전체 TC? 자동화 대상 TC?)
□ 인력 구성과 외부 컨설팅 투입은 어떻게 변했나
□ 유지보수 비용이 포함됐나
□ 우리와 비슷한 규모·업종의 레퍼런스 콜이 가능한가
```

### 기존 자산 이관 — "폐기 재구축이 아니라 흡수 재활용"

웨비나 Q&A 답변의 원칙이다. 자산별로 정리한다.

| 기존 자산 | 이관 방식 | 확인할 것 |
|---|---|---|
| 엑셀 수동 테스트 | 일괄 가져오기 | 단계·기대 결과가 칸으로 분리돼 있나 (8-05 규칙으로 정리 후 가져오기) |
| Selenium · Playwright 스크립트 | 그대로 CI/CD에서 실행, 결과만 테스트 관리로 수집 | 결과 포맷 연동, 요구사항 링크 |
| JMeter 성능 스크립트 | 시나리오를 재구성해 성능 테스트로 | 부하 모델 동등성 (트랙 5) |
| Jira · ServiceNow 등 ALM | 양방향 커넥터 | 요구사항 변경 → 영향 TC 식별, 실패 → 결함 티켓 자동 생성, 요구사항 커버리지 |

**이관 매트릭스**도 웨비나의 권고다. 우리 시스템 목록을 세 그룹으로 나눈다.

| 그룹 | 의미 | 예 |
|---|---|---|
| 기본 지원 | 추가 작업 없이 자동화 가능 | 웹, SAP GUI |
| 커넥터 필요 | 제공 커넥터 설정으로 가능 | ALM, 메신저 |
| 커스텀 | 직접 개발 필요 | 사내 레거시 프로토콜 |

"190개 이상 기술 지원", "50개 이상 ALM 커넥터"는 웨비나 발표 수치다. **개수가 아니라 우리 목록의 그룹 분포**가 이관 범위를 결정한다.

### PoC 설계 — 2~4주

```text
[PoC 계획서]
목적       야간 회귀 리드타임을 줄일 수 있는지 검증
대상       실제 회귀 세트 1개 (웹 30 TC + SAP 10 TC)  ← 데모 앱 금지
기준선      PoC 시작 전 AS-IS 리드타임 2회 측정 (8-01 형식)
성공 기준   (시작 전 합의)
           - 리드타임 50% 이상 단축
           - AI 생성 자동화의 어서션 누락 0건 (감사 후)
           - 자율 실행 결과 일치율 ≥ 90% (5회 반복)
           - 보안 심의 질문 7개 답변 완료 (8-07)
실패 포함   UI 변경 1회 주입, 데이터 변동 주입, 네트워크 지연 주입
비교군      같은 세트를 Playwright Agents 조합으로도 수행 → 한계 가치 측정
비용       라이선스 + 모델 호출 + 인프라 + 투입 인력 시간
종료 기준   2주차 중간 점검에서 성공 기준 2개 이상 불가 판단 시 조기 종료
산출물      측정표, 발견된 제약 목록, 12개월 로드맵 초안
```

**비교군이 이 계획서의 핵심이다.** "도입 전보다 좋아졌다"가 아니라 **"무료 대안보다 이만큼 더 좋다"** 를 보여야 비용이 설명된다.

### 가중치 평가표

| 기준 | 가중치 | 벤더 A | 벤더 B | 벤더 C | OSS 조합 |
|---|---|---|---|---|---|
| 우리 시스템 커버리지 (이관 매트릭스) | 25% | | | | |
| PoC 리드타임 개선 | 20% | | | | |
| 거버넌스·감사·온프레미스 | 15% | | | | |
| 기존 자산 흡수 비용 | 15% | | | | |
| 총비용 (3년) | 15% | | | | |
| 사용자 역량 적합 (로우코드/코드) | 10% | | | | |
| **가중 합계** | 100% | | | | |

가중치는 **점수를 보기 전에** 정하고 서명한다. 점수를 본 뒤 가중치를 바꾸는 순간 평가표는 결론을 정당화하는 도구가 된다.

### 테스터의 역할은 어떻게 바뀌나

| 줄어드는 일 | 늘어나는 일 |
|---|---|
| TC 타이핑, 스크립트 반복 수정 | 수용 기준·미션 설계 (8-06) |
| 실행 버튼 누르기, 결과 복사 | 에이전트 스펙·평가셋 설계 (8-03) |
| 실패 로그 1차 분류 | 결정 테이블·승인 게이트 설계 (8-04) |
| 보고서 수작업 | 리스크 판단과 경영진 보고 (트랙 7) |

웨비나 발표자 스스로 데모용 요구사항·TC 40~50개를 **Autopilot으로 만들었다**고 했다. 만드는 일은 싸졌다. **무엇이 맞는지 판단하는 일**의 가치가 올라갔다.

## 왜 채용시장이 요구하는가

- 도구 도입 결정에 QA가 **평가자로 참여**하는 경우가 늘었다. 데모에 감탄하는 사람이 아니라 **PoC와 평가표를 설계하는 사람**이 필요하다.
- 면접 질문: **"새 테스트 도구 도입을 제안한다면 어떻게 진행하겠습니까?"** — 기준선 측정, 사전 합의된 성공 기준, 비교군, 종료 기준을 말하면 리드 수준 답변이다.
- 면접 질문: **"AI가 테스터를 대체할까요?"** — 성숙도 5단계와 역할 변화 표로, 줄어드는 일과 늘어나는 일을 구체적으로 답한다.

## 실습 과제

### 과제 1 — 벤더 주장 검증 질문지 (10분)

웨비나 수치 3개(6·9·12배, 자동화율 95%, 회귀 주기 수 주→수 시간)마다 위 질문 6개를 적용해 **벤더에게 보낼 질문 메일**을 쓴다. 트랙 7-07 원칙대로 요청과 기한을 맨 위에 둔다.

### 과제 2 — 이관 매트릭스 (15분)

우리 조직(또는 가상의 은행: 웹뱅킹, 모바일 앱, SAP 회계, 사내 레거시 대출 심사, Jira)의 시스템과 테스트 자산을 나열하고 세 그룹과 이관 방식을 채운다.

### 과제 3 — PoC 계획서 (20분)

위 양식을 모두 채운다. **성공 기준은 숫자로**, **비교군은 반드시** 넣는다.

### 과제 4 — 가중치 평가표 (10분)

가중치를 먼저 확정하고, 이 트랙에서 본 정보만으로 벤더 2곳 + OSS 조합을 **가점수**로 채운다. 점수마다 근거 출처(문서/웨비나/추정)를 표시한다.

### 과제 5 — 12개월 로드맵 1장 (20분)

```text
[결정 요청]  ○○ PoC 승인 (예산 ○, 기간 ○주)
[현재 위치]  성숙도 ○단계 — 근거: 리드타임 분해 결과 (8-01)
[0~3개월]   AI 증강: TC·자동화 생성, 어서션 감사 정책 (8-02, 8-07)
[3~6개월]   오케스트레이션: 야간 파이프라인 + 결정 테이블 + 승인 게이트 (8-04)
[6~12개월]  자율 실행·탐색 포트폴리오 확대 (8-05, 8-06), 에이전트 평가셋 운영 (8-03)
[통제 장치]  보안 심의 답변서, 감사 로그, 정책 코드 (8-07)
[측정]      분기별 리드타임 · 결함 탈출률 · 오탐률 · 에스컬레이션 비율
[리스크]    과대 기대 / 셀프호스팅 기능 제약 / 승인 병목
```

### 과제 6 — 판단 훈련과 면접 답변 (15분)

1. 실습 랩 **🧭 에이전틱 테스트 운영 판단 훈련**을 끝까지 푼다
